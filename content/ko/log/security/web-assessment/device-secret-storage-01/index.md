## 1. 학습 목표

설치형 애플리케이션의 비밀정보 보호를 `암호화되어 있는가` 하나로 보지 않고 **키가 어디서 생성되고, 어디에 저장되며, 누가 어떤 조건으로 사용할 수 있고, 언제 폐기되는가**로 나누어 본다.

## 2. 하드코딩과 기기별 키

소스·리소스·설정에 공통 비밀키를 하드코딩하면 배포물 하나의 분석이 전체 설치본의 비밀 노출로 확대될 수 있다. 반면 기기에서 개별적으로 생성한 키는 한 기기의 침해가 다른 기기의 키까지 직접 노출시키는 범위를 줄일 수 있다.

점검에서는 바이너리 문자열 검색만으로 끝내지 않고 설정, 로그, 백업, crash dump, export 기능까지 key material이 복제되는 경로를 찾는다.

## 3. OS 보안 저장소

모바일·데스크톱 OS는 애플리케이션 자격정보나 암호키를 보호하기 위한 보안 저장 API를 제공할 수 있다. 중요한 것은 API 이름보다 다음 속성이다.

- 다른 앱이나 일반 사용자 프로세스와 접근 경계가 있는가
- 기기 잠금·사용자 인증과 키 사용을 묶을 수 있는가
- 백업·동기화로 다른 기기에 복제되는가
- 키 자체를 export할 수 있는가
- 앱 삭제·계정 초기화·기기 폐기 시 어떻게 제거되는가

## 4. 하드웨어 백업 키의 의미

플랫폼에 따라 일부 키는 TEE, secure element, TPM 같은 하드웨어 보호 경계에서 생성·사용될 수 있다. 이런 구조에서는 private key material을 일반 애플리케이션 메모리로 export하지 않고 하드웨어 또는 격리된 서비스가 암호 연산을 수행하도록 설계할 수 있다.

하지만 `보안 저장소 사용 = 항상 별도 보안칩에 키가 존재`한다고 일반화하지 않는다. 기기·OS·알고리즘·정책에 따라 software-backed 구현이나 다른 보호 수준이 사용될 수 있다.

## 5. 키가 밖으로 나오지 않는다는 보장의 조건

non-exportable key라면 앱은 key handle을 통해 서명·복호화 같은 연산을 요청하고 결과만 받을 수 있다. 이 경우 raw private key를 직접 읽는 공격면은 줄어든다.

그러나 키 원문을 추출하지 못한다고 해서 키 오용까지 자동으로 막히는 것은 아니다. 공격자가 키 사용 권한을 가진 프로세스나 계정을 장악하면 **키를 빼내지 않고도 서명 oracle처럼 사용할 가능성**이 있다. 따라서 저장 위치뿐 아니라 키 사용을 허가하는 인증·ACL·실행 컨텍스트를 함께 본다.

## 6. 키 생명주기

키 보호는 저장만의 문제가 아니다.

```text
생성
→ 등록·신뢰 형성
→ 사용
→ 교체
→ 폐기
```

P2P 기기 신원 키라면 새 키 발급이 기존 peer의 신뢰를 어떻게 갱신하는지, 분실 기기의 키를 어떻게 폐기하는지, 오래된 자격정보가 재사용되지 않는지를 확인한다.

## 7. 민감 데이터와 로그

클립보드·입력 이력처럼 사용자가 복사하거나 입력한 데이터는 비밀번호, 토큰, 개인정보를 포함할 수 있다. 저장한다면 데이터 암호화 키의 보호와 함께 보존 기간, 동기화 범위, 사용자 삭제 기능, 로그 노출을 본다.

중복 탐지를 위해 digest를 저장하는 경우에도 원문 대신 digest를 쓴다는 사실만으로 안전성을 단정하지 않는다. 입력 후보 공간이 작거나 예측 가능하면 digest가 원문 추정에 이용될 수 있으므로 데이터 성격과 위협 모델을 함께 고려한다.

## 8. 공격자·방어자 관점

공격자는 `키 파일`만 찾지 않는다. 백업, 로그, dump, export, IPC와 **키를 대신 사용해 주는 인터페이스**를 찾는다.

방어자는 가능한 경우 기기별 키와 non-exportable 저장을 사용하고, 키 사용 권한을 최소화하며, 사용자 인증과 키 사용을 결합하고, 교체·폐기까지 생명주기로 관리한다.

## 9. 검증 포인트

허가된 테스트 기기에서 다음 사실을 확인한다.

- 공통 secret의 하드코딩 여부
- 기기별 key 생성 여부
- 실제 저장 backend와 hardware-backed 여부
- export 가능 여부와 key 사용 ACL
- 백업·동기화·로그·dump로의 복제 여부
- 신원 키의 교체·폐기 절차
- 민감 데이터의 저장·삭제·동기화 범위
