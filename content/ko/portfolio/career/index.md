> **읽는 방법**: 이 페이지는 이력서와 기존 프로젝트 자료를 연결하는 공용 안내 페이지다. **실무**, **교육·실습**, **개인·학업 프로젝트**, **분석·학습 기록**을 구분했다. 고객사 자료와 원본 진단 보고서는 공개하지 않는다. 설명에 적힌 수행 범위와 검증 수준이 각 항목의 경계다.

## 한눈에 보는 경력

| 업무 영역 | 역할 | 주요 업무 |
| --- | --- | --- |
| 보안 컨설팅 | 취약점 진단·기술 점검 | 웹·Android 앱·API 취약점 진단, 인프라 점검, 조치 요청과 이행점검 |
| 보안관제 | 이벤트·로그 분석 | WAF·IPS·방화벽·APT 이벤트 분석, SIEM 관제, 티켓·보고서 관리 |

보안관제에서는 발생한 이벤트를 로그와 대조하며 공격 여부와 영향을 판단했다. 이후 취약점을 사전에 찾아 재현하고 조치 결과까지 확인하는 업무로 이동했다. 현재는 웹·앱·API 진단과 서버·클라우드·DBMS·네트워크 장비 등 인프라 기술 점검을 수행한다.

## 1. 취약점 진단과 보안 컨설팅 · 실무

### 웹·앱·API 진단과 이행점검

취약점 진단 업무에서는 새 기능·서비스의 진단 대상을 파악하고, 주요정보통신기반시설 취약점 분석·평가 가이드와 회사 기준에 따라 점검한다. 웹 진단에는 주로 Burp Suite를 사용한다. 발견 사항은 재현 조건·영향·조치 방향을 산출물로 남기고, 조치가 완료되면 같은 경로를 다시 확인한다.

웹 진단 프로젝트에서는 동료와 점검 범위를 나누어 내·외부 페이지를 점검했다. 일반적인 점검에서 추가 취약점이 드러나지 않아 JavaScript 입력 처리 경로를 더 살폈고, 저장된 게시글에 접근할 때 실행되는 XSS를 재현했다. 원인과 조치 방향을 보고하고, 수정 후 스크립트가 실행되지 않는 것을 이행점검으로 확인했다. 고객사·서비스·요청값·원본 보고서는 공개하지 않는다.

### 인프라 점검과 자동화

ISMS 인증 준비 업무에서는 서버·클라우드·DBMS·네트워크·보안 장비·업무용 단말기를 대상별 방식으로 점검했다. 필요한 계정과 접근 권한을 요청하고, 스크립트 결과·장비 설정·담당자 인터뷰를 구분해 증적을 확보했다. 점검 결과를 바탕으로 위험 수용과 감소 항목을 구분하고 조치 시기를 정리했다.

공개 점검 가이드를 AI에 제공하고 **기준 해석 → 스크립트 작성 → 결과 검토**의 역할과 순서를 설계해 대상별 점검 스크립트 준비에 활용했다. 실제 적용 과정에서 수집 경로가 맞지 않는 경우를 확인하고, 컨테이너 안에서 실행되는 프로그램은 필요한 설정을 가져와 판단하도록 방법을 바꿨다. 모든 코드를 수작업으로 구현하거나 AI 모델을 직접 학습시켰다는 뜻은 아니다.

- [컨테이너 이미지 점검에서 범위와 실행 환경을 정한 기록](/log/security/infrastructure-assessment/container-image-scan-scope-01/)
- [취약점 대응 공지에서 공식 근거와 회신 항목을 다듬은 기록](/log/security/vulnerability-advisory-evidence-01/)

### 업무 자료 분석 도구

과거 진단 문서를 찾는 데 드는 시간을 줄이기 위해 문서 서식에서 취약점 제목을 추출하는 스크립트를 작성했다. 이후 요청에 맞춰 보고서의 수행자·참여 프로젝트를 집계하고 연도·월별로 조회하도록 목적을 바꿨다. 내부 문서와 원본 코드는 공개하지 않으며, [가상 DOCX 기반 공개 재현 자료](/portfolio/development/report-indexer/)에서 추출·기간 필터·집계 과정을 확인할 수 있다.

## 2. 보안관제 · 실무

보안관제 업무에서 WAF·IPS·방화벽·APT 이벤트를 SIEM과 원천 로그로 분석하고 티켓으로 관리했다. 주간에는 고객사 보안 담당자와 협업하고 야간에는 단독으로 관제했다. 당일 이벤트 기록과 주간 보고서를 작성하고 보안 뉴스를 선별해 전달했다. 이 경험은 진단에서 재현한 행위가 운영 로그에 어떤 흔적으로 남는지도 함께 생각하는 기반이 됐다.

## 3. 보안 연구와 교육·실습

### AI 활용 오픈소스 퍼징 · 자율 연구

2026년 10월 시작한 스터디에서 AI 서비스를 오케스트레이터로 활용해 오픈소스 소프트웨어를 퍼징하고 결과를 검토했다. libConfuse에서 발생한 크래시 3건을 관리자에게 보안 보고서로 제출했다. **취약점 인정과 CVE 부여 여부는 확인되지 않았으므로 성과로 주장하지 않는다.** 스터디 동료의 CVE도 내 성과로 포함하지 않는다. 공개 가능한 재현 자료는 제보 상태를 고려해 별도로 검토한다.

### KISA 헌팅마스터 2기 · 교육

2025년 리버싱·모바일 트랙을 수료했다. 모바일 게임의 동작을 분석하고 Frida 등을 활용해 체력·재화 값 조작을 실습했다. AFL++·WinAFL 기반 퍼징을 처음 접했으며 이후 오픈소스 분석으로 학습을 이어갔다. 교육 실습의 결과를 실제 서비스 취약점 발견으로 소개하지 않는다.

### 노말틱 모의해킹 취업반 · 교육

2024년 10월부터 2025년 3월까지 웹 서비스 구현과 교육생 간 상호 모의해킹을 수행했다. SQL Injection, XSS, CSRF, 파일 업로드·다운로드, 인증·인가 문제를 점검하고 재현 과정과 조치 방향을 보고서로 작성했다. 기존 결과보고서에는 교육용 웹앱의 취약점과 권고안이 담겨 있다. 원본의 실습 사이트 주소·응답·개인정보는 공개하지 않는다.

### 온프레미스 보안 인프라 구축 · 개인 실습

가상화 환경에 라우터와 방화벽을 두고 망을 분리한 뒤, 웹 실습 서버·IPS·IDS·WAF·SIEM을 연결했다. VyOS, pfSense, Snort, Security Onion, ModSecurity, Splunk 등을 사용해 구성 요소를 단계적으로 추가하고 공격 테스트와 로그 변화를 관찰했다. 기존 포트폴리오 PDF는 구축 절차와 화면 중심의 실습 자료이며, 실제 고객 환경 구축 이력은 아니다. 공개용 구성도와 글은 원본 자료를 검토해 별도로 정리할 예정이다.

## 4. AI·자동화·개발 프로젝트

### 차량 재식별 · AI Bootcamp 기업 협업 과제

2022년 7월부터 2023년 2월까지 코드스테이츠 AI Bootcamp에 참여했다. 넥스트랩 협업 과제에서는 차량 재식별 작업을 개별 수행했다. AI Hub 이미지에서 차량 영역을 추출하고 JSON 메타데이터를 처리한 뒤 **기존 학습 모델**을 적용해 서로 다른 각도에서 촬영된 동일 차량의 식별 결과를 비교했다. 재식별 알고리즘 3종을 비교하고 제공된 CCTV 영상으로 시연했다. 이는 영상 AI 모델 **활용·비교** 경험이며, 기반 모델을 새로 학습시켰다는 뜻이 아니다.

### 이미지 분류 모델 실험 · 학업 과제

MNIST와 CIFAR-10 과제에서는 VGG 계열의 합성곱·풀링 구조를 데이터 크기에 맞게 구성하고 학습률과 배치 크기를 바꾸며 손실 변화를 관찰했다. 학습이 불안정했던 시도와 실행 환경의 한계도 과제 보고서에 기록했다. 차량 재식별 과제와는 별개의 학업 실험이다.

### 이메일 정보 수집 자동화 · RPA 교육 프로젝트

UiPath 교육 과정에서 이메일의 정보를 추출하고 웹 연계 데이터를 수집하는 흐름을 구현했다. 오류 데이터를 포함한 성공·실패 사례를 나누고 결과를 보고하는 과정을 실습했다. 보안 운영 현장에 배포된 도구로 소개하지 않는다.

### 설문 웹페이지 · 학업 프로젝트

설문 제작·응답·통계 화면과 MySQL 데이터 구조를 설계·구현했다. 남겨진 보고서에는 구현된 화면과 미구현 테이블·기능이 함께 기재돼 있어, 설계안 전체를 완성 기능으로 소개하지 않는다.

### 증권 OpenAPI 연동 프로그램 · 학업 프로젝트

키움 OpenAPI를 사용해 주문·취소 등 HTS 기능과 자동 매매·백테스트 구상을 다룬 캡스톤 프로젝트다. 당시 보고서에는 **구현된 일부 기능, 동작 오류, 향후 계획**이 구분돼 있다. 계획했던 자동 매매·백테스트를 완성 성과로 주장하지 않는다.

## 공개 범위와 다음 작업

이 페이지는 경력과 기존 포트폴리오 **원본을 그대로 게시하는 자료실이 아니다.** 실무 기록은 고객 환경을 일반화했고, 교육·학업 자료는 완료된 작업과 계획·미구현 부분을 구분했다. 내부 산출물이나 현재 진행 중인 제보의 상세 재현 내용은 공개하지 않는다.

대표 작업과 증빙은 [포트폴리오](/views/portfolio/)에서 확인할 수 있다. 실무 경험과 새로 작성한 합성 재현 자료는 각 글에서 구분한다.
