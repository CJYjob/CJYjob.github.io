# 점검 스크립트 현업 재사용 전 확인표

> - 공개 후보 문서입니다. 특정 고객이나 환경 정보는 없습니다.
> - 이 표는 **실행 전 확인용**입니다.
> - 확인은 시험 환경이나 사본에서 합니다.
> - 고객 환경에서 이 표를 위해 무언가를 실행하거나 바꾸지 않습니다. 운영 환경 실행은 고객 승인 절차를 따릅니다.

| # | 영역 | 확인할 것 | 확인 방법(시험 환경) | 통과 기준 |
|---|---|---|---|---|
| 1 | 대상 | 점검 대상의 OS·제품·버전이 스크립트 지원 범위 안인가 | 스크립트 상단 주석의 지원 범위와 자산 목록 대조 | 범위 밖 대상은 실행 목록에서 빼거나 "수동"으로 표시 |
| 2 | 버전 | 스크립트 안의 버전 표기, 파일명·폴더 버전, 출력에 찍히는 버전이 같은가 | 세 곳을 나란히 비교 | 모두 같음. 다르면 하나로 고친 뒤 다시 검증 |
| 3 | 검증본 = 실행본 | 시험에서 통과한 파일과 실제로 넘길 파일이 같은 파일인가 | 두 파일의 해시(예: SHA-256) 비교 | 해시 일치. 반출 폴더에 옛 파일이 남아 있지 않음 |
| 4 | 권한 | 필요한 권한(일반/관리자)과 권한이 부족할 때의 동작 | 일반 계정으로 시험 실행 | 권한 부족이 "양호"나 "취약"이 아니라 "확인 불가"로 기록됨 |
| 5 | 위험 명령 | 삭제·설정 변경·서비스 재시작·계정 변경·외부 통신이 없는가 | 정적 검사(패턴 검사) + 코드 읽기 | 0건. 꼭 필요한 동작은 스크립트 밖 수동 절차로 분리 |
| 6 | 위험 명령(우회) | 변수 조립·별칭·외부 파일 호출로 숨은 명령이 없는가 | 코드 읽기, 호출하는 외부 명령 목록 작성 | 목록의 모든 명령이 읽기 전용 |
| 7 | 수집 실패 | 명령 실패·시간 초과·중단이 "완료"로 기록되지 않는가 | 실패하는 가짜 명령, 시간 초과를 넣어 시험 | 실패 사유와 종료코드가 결과에 남음 |
| 8 | 빈 입력 | 파일은 있는데 내용이 없을 때 `nodata`로 남는가 | 0바이트·공백만 있는 입력 시험(예제 1) | 빈 입력이 정상 수집으로 기록되지 않음 |
| 9 | 인코딩 | 수집 도구의 기본 저장 인코딩과 파서의 읽기 방식이 맞는가 | 같은 내용을 UTF-8, UTF-8 BOM, UTF-16LE/BE로 저장해 시험(예제 2) | 모든 인코딩에서 같은 결과 |
| 10 | 로캘·출력 형식 | 언어 설정·명령 출력 형식이 다를 때 깨지지 않는가 | 다른 로캘, 다른 버전의 출력 샘플로 시험 | 값 추출 실패가 "없음"이 아니라 "확인 불가"로 남음 |
| 11 | 출력 형식 | 결과 파일이 분석 단계가 읽는 형식을 지키는가 | 파서로 다시 읽어 항목 수·필드 수 확인 | 모든 항목이 있고 필드 수가 일정 |
| 12 | 실행 흔적 | 결과에 실행 시각·호스트·스크립트 버전이 찍히는가 | 시험 출력 확인 | 세 값 모두 있음 |
| 13 | 회귀 | 수정 후 정상 입력·취약 입력의 결과가 바뀌지 않았는가 | 수정 전후 같은 입력으로 결과 비교(diff) | 의도한 사례만 바뀜 |
| 14 | 기록 | 검증 회차·결함·수정 내용이 기록에 남았는가 | 검증 보고서와 변경 이력 확인 | 회차별로 남음 |
