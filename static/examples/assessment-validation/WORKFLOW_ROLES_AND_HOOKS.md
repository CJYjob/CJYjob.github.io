# AI 점검 워크플로 — 역할, 검토 순서, 훅 (공개용 설명)

> 공개 글 재료입니다.
> - 실제 과제명, 대상, 경로, 건수, 판정 결과는 넣지 않았습니다.
> - "정의"는 설정 파일에 적힌 규칙입니다.
> - "실행 근거"는 작업 기록에서 확인된 것입니다.
> - 둘은 다른 주장이므로 따로 적었습니다.

## 1. 전제

- 일부 점검 대상은 AI가 직접 접속할 수 없는 내부망에 있습니다.
- 그래서 일은 다음 순서로 나뉩니다.
  1. AI가 읽기 전용 점검 스크립트를 만듭니다.
  2. 사람이 내부망에서 스크립트를 실행합니다.
  3. 사람이 결과 파일만 가져옵니다.
  4. AI가 결과를 분석합니다.
- 흐름은 이 반입 지점에서 한 번 끊깁니다.

## 2. 역할별 입력·출력과 검토 순서

| 순서 | 역할 | 입력 | 출력 | 하지 않는 것 |
|---|---|---|---|---|
| 1 | 기획 | 범위, 공통 원칙, 누적 교훈 | 대상·항목·판정 기준·수용 기준·시험 계획 | 스크립트 작성, 판정 |
| 2 | 스크립트 개발 | 기획 문서 | 점검 스크립트, 실행 가이드, 항목 매핑표 | 상태 변경 명령, 외부 통신, 판정 |
| 3 | 스크립트 검증 | 스크립트, 기획 문서 | 검증 보고서(결함과 심각도) | 스크립트 직접 수정(개발로 되돌림) |
| - | (사람) 실행·반입 | 핸드오프 묶음 | 결과 파일 | - |
| 4 | 분석 | 결과 파일, 기준 | 항목별 판정과 근거 위치 | 결측을 추정으로 채우기 |
| 5 | 검증 핸드오프 작성 | 분석 결과 | 항목과 근거 위치만 담은 문서(**판정 라벨 제외**) | - |
| 6 | 독립 재판정 | 검증 핸드오프, 원본 결과 | 재판정 → 그다음 분석과 대조한 차이 목록 | 분석 결과를 먼저 열기 |
| 7 | 보고 | 분석 + 재판정 차이 | 보고서 | 검증되지 않은 주장 |
| 8 | 학습 정리 | 이번 작업 기록 | 일반화한 교훈(대상 식별정보 제외) | 판정 변경 |

**넘김 조건 (정의)**
- 검증 단계가 결정론적 검사기에서 통과를 받아야 합니다.
- 동시에 치명·중 결함이 0이어야 합니다.
- 그렇지 않으면 개발로 되돌립니다.
- 되돌림은 최대 3회입니다. 그래도 남으면 멈추지 않고 사람이 볼 "확인 필요" 목록에 올립니다.

## 3. 훅과 검사기

| 장치 | 검사 시점 | 하는 일 | 적용 범위 | 한계(코드에서 확인) |
|---|---|---|---|---|
| 쓰기 가드 | AI가 파일을 쓰거나 고치기 직전 | 삭제·서비스 변경·계정 변경·외부 통신 같은 금지 패턴이 있으면 쓰기를 거부 | 경로가 "스크립트" 폴더나 "핸드오프" 폴더 아래인 파일만. 문서·데이터 확장자(.md .txt .json .csv)는 제외 | 경로 기준이라 다른 폴더에 쓰면 검사하지 않음. 문자열 매칭이라 주석에도 걸리고 조립된 명령은 못 잡음. 입력 해석 실패 시 허용 |
| 로그 점검 | AI가 작업을 끝내려 할 때 | 가장 최근 작업 폴더에 산출물은 있는데 단계별 로그가 없으면 종료를 1번 막음 | 작업 루트 아래 작업 폴더 | 1회만 막음(표식 파일). 로그 내용의 질은 보지 않음 |
| 정적 검사기 | 검증 단계가 매 회차 직접 실행 | 금지 패턴 + 결과 형식 표식이 있는지 검사 → PASS/FAIL | 지정한 스크립트 폴더 | 형식 표식은 "문자열이 있는지"만 봄. 동작은 합성 입력 실행으로 따로 확인해야 함 |

## 4. 정의와 실제 실행 (일반화한 결과)

| 규칙 | 정의 | 실행 근거 | 확인된 결과 |
|---|---|---|---|
| 최대 3회 재작업 | 있음 | 재작업 루프가 여러 작업에서 돌았음 | 결함 때문에 되돌린 횟수는 모두 1회. **3회 상한과 "확인 필요로 올리기" 분기는 한 번도 실행되지 않음** |
| 정적 검사기 | 있음 | 검증 단계 기록에 실행 흔적 | **FAIL은 기록되지 않았음.** 되돌린 사유는 모두 검증 에이전트가 합성 입력을 돌려 찾은 결함 |
| 쓰기 가드 | 있음 | 설정에 등록됨 | **실제 차단 기록은 찾지 못했음**(일부 기간은 기록 없음). 네트워크를 쓰는 수집 스크립트는 의도적으로 가드 경로 밖에 둠. 가드 경로 밖에서 관리한 점검 도구에는 적용되지 않았음 |
| 로그 점검 | 있음 | 발동 표식 파일 | **여러 작업 폴더에 발동 표식이 남아 있음** → 실제로 종료를 막았음 |
| 라벨 없는 독립 재판정 | 있음 | 검증 핸드오프 문서와 재판정 로그 | 일부 작업에서 실행. 그 작업들에서는 핸드오프에 라벨이 없었고, 재판정을 먼저 하고 대조를 나중에 했다는 기록이 있음. **모든 작업에 적용되지는 않았음** |
| 전 단계 수행 | - | 단계별 로그 | 기획부터 학습 정리까지 모두 남은 작업은 일부. 나머지는 준비 구간까지만 하거나 결과 구간만 함. 주력 인프라 점검 다수는 이 흐름 밖에서 진행 |

## 5. 누가 무엇을 했나 (근거가 확인된 범위)

| 일 | 주체 | 근거 수준 |
|---|---|---|
| 빈 증적 결함 발견 | 검증 에이전트(합성 0바이트 입력 실행) | 작업 기록 |
| 빈 증적 수정과 재시험 | 개발 에이전트 → 검증 에이전트 | 작업 기록 |
| 인코딩 결함 발견 | 사람이 수집한 결과에서 대량 "없음"이 나온 뒤 파일 앞바이트를 확인 | 작업 기록. 첫 의심을 누가 제기했는지는 기록 없음 |
| 인코딩 대응 방향(수집 스크립트 통일, 파서 견고화 등) | 사용자 결정으로 기록됨 | AI가 남긴 로그 속 기록. 사용자 원문 발화는 없음 |
| 인코딩 수정과 5종 재시험 | 개발 에이전트 → 검증 에이전트 | 작업 기록 |
| 반출 폴더에 수정 전 파일이 남은 것 적발 | 검증 에이전트 | 작업 기록 |
| 최종 판정 확정 | 사용자 확정으로 기록됨 | 로그 속 기록 |
| 워크플로 구조 설계 | **확인 불가.** 생성 당시 기록이 없음 | 사용자 기억에 따른 진술로만 쓸 수 있음 |
| 결과 수집 실행 | 사람(로그상 "운영자") | 누구인지 기록 없음 |
